# 网页仿真工作台

网页复用 `supernode-modeling` skill 对应的 `supernode_sim` 数值引擎。普通仿真使用 `analysis.run` / `write_report`，大规模结构化推理自动选择 `run_streaming`，请求服务使用 `simulate_serving` / `write_serving_report`；浏览器不生成模拟指标。

调用 `supernode-modeling` skill 时，默认自动准备并打开此网页。可复用启动器负责检查依赖、复用匹配服务及避让占用端口；详细调用约定见 [Skill 前端流程](../skills/supernode-modeling/references/frontend.md)。以下手动启动方式继续可用。

## 启动

要求 Python 3.11+，项目依赖与命令行一致。已有 `.venv` 的工作区直接运行：

```powershell
.\.venv\Scripts\python.exe -m supernode_sim web
```

首次安装的环境使用：

```powershell
python -m pip install -e ".[test]"
python -m supernode_sim web
```

打开终端显示的网址，默认是 `http://127.0.0.1:8765`。终端保持运行；使用 Ctrl+C 停止服务。也支持 `snmodel web` 或 `python -m supernode_sim.web`。

```powershell
python -m supernode_sim web --port 8766 --output outputs/web
```

服务只面向本机回环地址。Python 引擎在本机运行，页面、输入、仿真产物均留在本地项目中。网页没有外部 CDN 或前端构建依赖。

## 配置并运行

1. 选择预设。预设来自项目 `examples/` 中可通过完整场景校验的文件，保留来源与假设；搜索规范、校准片段不会当作完整场景。
2. 调整负载、硬件、并行度、精度与 offload。表单支持拓扑模板、每主机卡数、单卡 HBM（GB）、SU/SO 带宽（GB/s）以及时延、吞吐目标。显式链路配置通过 JSON 修改，避免模板控件误改原图。推理输入和输出长度支持逗号分隔列表；变长 batch 的每个长度都会保留。列表长度必须与 batch 匹配。训练使用序列长度、梯度累积和训练步数。
3. 需要修改模型结构、显式链路、完整精度或其他字段时，使用高级 JSON 编辑器。可导入与导出 JSON 完整场景。引用校准文件的 YAML 应先用命令行解析，网页导入 `config.resolved.json`；网页请求不读取用户指定的本地文件路径。
4. 选择“离散事件仿真”“解析估算”或“请求级服务”，校验配置并开始运行。所有输入由对应 Pydantic schema 严格校验。普通并行乘积为 `TP × PP × EP × DP = NPU 数`，FSDP 必须整除 DP；服务模式的总部署卡数还需乘独立实例数。
5. 观察运行阶段、经过时间和日志。当前引擎没有事件级进度回调，因此不提供虚构的完成百分比。可以取消正在执行的任务；取消会终止独立仿真进程。
6. 运行结束后查看结果，下载结果 JSON、解析后配置、中文报告和可用 CSV/Trace 文件。历史运行使用提交时的配置，后续表单编辑不会修改已完成结果。

为控制主机资源，网页后台同一时间执行一个任务；一个服务任务内可以模拟多个隔离实例。网页提供 `estimate` / `simulate` / `serve`，不会擅自缩小输入；批量扫描、SU 搜索、Feedback 仍使用原命令行/API。

### 自适应主机内存

每个 Web 计算进程在构图前设置内存硬上限，覆盖仿真、估算、服务和独立案例。默认取物理内存一半与当前可用内存一半的较小值；Windows 同时考虑可用提交额度，Linux 同时考虑 cgroup v1/v2 容器限额与当前使用量，macOS 读取物理内存与可回收页。无法探测时保守使用 1 GiB。主机预算独立于配置中的 NPU HBM/CPU DRAM，不改变模拟硬件、模型、精度或负载。

Windows 使用 Job Object 限制进程提交内存；POSIX 使用 `RLIMIT_AS` 限制地址空间（包含映射）。无法建立保护或可用预算不足 128 MiB 时明确失败，不启动无保护的计算。超出预算后记录可读错误、保留输入并释放任务槽位，可继续提交下一项任务。已经运行的服务需要重启以加载代码更新。

可在启动服务前显式设置预算（单位 MiB），用于独占服务器或与其他程序共享的机器；显式预算仍不超过启动时可用内存的 75%，不接受 0 来关闭保护：

```powershell
$env:SUPERNODE_WEB_MEMORY_MIB = '8192'
python -m supernode_sim web
```

Linux / macOS 使用 `SUPERNODE_WEB_MEMORY_MIB=8192 python -m supernode_sim web`。不设置时自动适配主机，没有固定 4 GiB 上限；更大机器可获得更大的预算。预算记录在任务日志与 `host_memory_limit_bytes`，普通/流式任务完成时同时记录 `host_peak_memory_bytes`（Windows 为私有提交峰值，POSIX 为 RSS 峰值，不能跨平台直接比较）。

大规模 `simulate` 根据卡数、层数、最长输出、TP/EP 与主机预算选择图保留策略；此规模估计仅用于主机内存策略，不是仿真时间或设备容量的估计。结构化 inference 且 DP=PP=1、未启用 megakernel/PD 时可按现有屏障分块执行，支持原有 SP/投机路径；流式缓存预算为进程预算的 10%，按实际需要分配并按字节淘汰。强机器可容纳更大的完整图及缓存。其他配置继续使用普通引擎并受到同样的内存硬上限保护，不通过改变参数或静默切换语义来完成任务。

流式报告保留 TTFT/TPOT、SLO、算子归因、资源使用、逐池内存峰值和实际分块 CSV；不保留逐算子回放、逐张量生命周期及组件峰值构成，不产生假的完整图下界。网页明确显示这些明细不可用。通信汇总仅含完整执行成功的分块，中断分块的部分传输未计入。需要完整生命周期时使用普通 CLI 的明细路径并自行预留主机资源；Web 的保护不改变 CLI 资源策略。

网页请求限制为 2 MiB，batch size 上限为 100,000，超过时明确拒绝，防止配置校验阶段自动展开过大的长度列表。更大负载使用原 CLI/API。内置预设需要源码仓库的 `examples/`；在没有示例文件的独立安装中，可从完整 JSON 配置导入。

## FP4 512 卡 / EP128 独立案例入口

左侧 **FP4 案例** 和模型预设下的链接打开 `/fp4-case.html`，默认 950DT 96 GB/卡，可切换 950PR 128 GB/卡。该案例使用原实验的 CED/CSA2/Engram 与 POD/DFlash 分阶段模型，输入为独立 `CaseConfig`，任务模式为 `pod_dflash`，不转成普通场景 `Config`。同一后台队列负责运行、取消、输入快照及报告；案例历史在案例页查看。具体默认负载、时延口径、复跑命令与检查点对照见 [案例说明](fp4-512-case.md)。

## 请求级服务仿真

推理场景选择“请求级服务 · FCFS 成批”，出现独立的请求编辑区。可一键载入成对的 synthetic 模型/请求示例，再修改实例数、每批请求上限、成批等待、调度开销及客户端 TTFT/TPOT 阈值。请求表保留 ID、到达秒数、输入与输出 token；大列表可通过服务 JSON 导入、编辑和导出。等待/开销/SLO 控件标明毫秒，提交时仅换算一次为秒。

服务参数独立于模型 Config，固定 batch/长度/targets 控件在服务模式不用于调度；原配置仍保留。服务模式明确要求 inference、DP=1，暂不支持 PD/投机服务调度。每实例复制完整硬件与网络资源，页面展示每实例卡数与总部署卡数。切换训练时退出服务模式，不将服务负载混进训练配置。

未应用或无效的模型/服务 JSON 保留原文本；载入示例或复制历史不会悄悄覆盖它们。提交保存 `input.config.json` 和 `input.serving.json`；历史只读，“复制所选运行的完整输入到编辑区”同时恢复两份快照。普通历史没有服务负载时不会借用当前服务草稿，迟到响应也不会覆盖新选择。

服务结果包括：完成/失败请求、完整观察窗口、成功吞吐、联合 SLO goodput、等待与客户端/服务端 TTFT、TPOT/E2E 分位数、逐请求状态和相对时钟批次时间线。单 token TPOT 显示不适用，失败请求显示未完成；任务完成、请求成功和 SLO 达标分别呈现。没有适用数据时显示空值，不填零。

请求/批次表最多显示各 200 行、执行形状最多 40 项；页面标注展示数量。总体分位数和吞吐来自引擎完整请求集，不在前端按截取行重算。时间线使用相对时钟避免大绝对时间损失精度。服务结果不显示不存在的固定 batch 关键路径、通信/内存总图；每批执行的详细证据仍保存在下载结果中。

网页服务负载上限为 10,000 请求、每批 1,024 请求、128 个实例，同时仍受 2 MiB 请求限制；超限直接报错，不截断或缩批。更多请求使用 CLI。当前服务调度为固定成批 FCFS，不含连续 batching、抢占或异构 PD；有限样本 P99 不是生产保障。

## 训练账本与执行证据

训练结果新增模型 MFU、全部 NPU 执行计算比例、角色 FLOPs 条图、阶段/dtype 表以及独立 CPU 账本。MFU 分子只含当前模型前向/反向代理，重算、优化器与辅助工作另列；按 dtype 裸峰值归一，不当作设备忙碌率。估算或旧结果缺少账本时不虚构显示。

“执行粒度与校准证据”分别展示 operator trace 展开、kernel 与 collective 计时命中、分阶段覆盖、未匹配/跳过原因。trace 覆盖不是准确率；eligible 为零时显示无适用事件。实际子算子表保留父事件、顺序、阶段与声明的矩阵维度，采样明细与全部统计分别标注。服务结果按真实批次执行形状选择证据，不把不同形状覆盖混算。

## 独立输入总览

点击左侧导航的“输入”，进入独立的输入配置页面。五个分区分别展示模型、拓扑、硬件参数、并行配置和 Workload；常用参数支持直接编辑，完整嵌套配置通过可展开明细核对与修改。

- **当前编辑配置**：进入编辑状态后，直接修改展示的模型参数、硬件容量/带宽、并行度、负载与目标等字段。改动同步到实验页、完整 JSON 和下一次仿真提交的配置，修改字段会记录为用户输入来源。
- **完整字段编辑**：嵌套结构、显式链路、路由、rank 映射、逐请求长度数组等可通过完整字段的编辑入口修改。数组保留精确顺序；容量、带宽和时延按控件标注的单位换算回引擎单位。
- **统一校验**：可先完成多字段调整，再校验完整配置。类型错误、并行乘积不匹配、batch 与长度列表不一致等会明确提示并保留修改。校验通过后，返回实验页开始模拟，使用的就是修改后的参数。
- **运行配置快照**：历史运行保持只读。使用“复制为当前配置并编辑”创建独立的当前配置后再修改；已有任务、运行中的任务及其保存的输入不受影响。
- **导出与保存**：可以下载当前查看的完整配置。当前页编辑内容用于本标签页的后续实验；启动仿真后，服务在新任务目录保存 `input.config.json` 和解析后的配置，便于复现。刷新或关闭页面前，可导出尚未运行的修改。

这里编辑的是 `supernode-modeling` skill 调用 `supernode_sim` 时使用的场景 `Config`。结构化模型的参数量由张量形状派生，修改相关结构后经校验重新计算；硬件、精度和并行策略仍遵循原引擎的严格约束。

模型总参数量、每 token 活跃参数量及公开约数分别展示。硬件容量和带宽使用十进制 GB、GB/s，保留原始字段与原始单位。并行关系仍为 `TP × PP × EP × DP = NPU 数`，FSDP 是 DP 子组，SP 复用 TP rank。并行区提供 SP 开关及派生度数（开启为 TP，关闭为 1），同步显示在执行摘要、输入总览及拓扑设备详情；当前引擎要求结构化推理、TP > 1、PP = 1。推理逐请求的变长输入/输出长度保留；Batch 是每个 DP 副本的负载。SU 域数可以从总卡数与每 SU 卡数推导，原生配置未声明的 SO 域数不推测。

## 图表口径

- “展示依据”统一控制集群拓扑和执行计划：草稿修改即刷新；选择运行时读取其独立快照，异步响应不会覆盖较新选择。
- 拓扑按 Full mesh / Mesh / Clos / Fat tree / Explicit 分别绘制。SO 独立面板默认位于 SU 图上方，持续展示卡组接入、SU gateway、SO spine 和共享上联；支持点击 SU 下钻、分别分页和设备 rank/host/并行坐标详情。显式图的 SO 面板只提取 `domain=SO` 的真实边，无 SO 边时明确留空；显式图展示有向边与孤立设备，大图明确标注截取数量。Clos / Fat tree 按当前引擎均为单 spine 模型；图形不代表实测报文路径或拥塞动画。
- 执行计划根据训练/推理负载、并行配置及加速特性生成；任务服务状态独立呈现。结果的 `execution_summary` 从全部已保留轨迹聚合，最多 40 个阶段，超出部分合并；阶段时间跨度可能重叠，不能加和当作墙钟耗时。部分执行、仅估算和旧任务无摘要均明确标注。
- 逻辑 transport payload 与 SU/SO 等链路类别的逐跳物理字节量是不同口径，不能直接相加。通信语义分类和 collective 分类是同一 payload 的不同视角。
- 通信汇总来自完整计划事件图。容量失败时，不能把完整图的计划流量当作已完成传输量。
- `estimate` 仅给出必要耗时下界；乐观调度的内存峰值忽略争用，不能证明容量或 SLO 可行。
- `simulate` 的实际峰值、资源使用与时间线来自离散事件执行。资源平均利用率不等于任意时刻的瞬时利用率。
- `infeasible`、`slo_failed` 与程序执行失败分别呈现。不可行方案仍保留输出，服务不会自动增加硬件容量。
- 推理 TTFT 从执行开始计时，TPOT 是每条序列首 token 后的平均间隔；batch 指标取请求中的最大值。只生成一个 token 时 TPOT 无定义。吞吐是完整执行期间的输出 token 数除以耗时，不是生产排队或 P99 指标。
- 为控制浏览器负担，资源、内存池与时间线展示有数量上限，页面标注抽样或截取情况。完整导出文件仍遵循原引擎的明细导出策略；下载文件清单以该次运行实际产物为准。
- 不同组件各自的独立峰值不能相加当作设备同时峰值。组件明细与参数来源可在下载报告中进一步审计。

## 文件与接口

每次运行在 `outputs/web/<任务 ID>/` 下保存独立配置、任务状态与报告产物。重启后读取历史任务；被服务中断的运行不会伪装成成功，也不会自动重跑。

主要本地接口：

| 请求 | 用途 |
|---|---|
| `GET /api/health` | 服务身份、项目/输出目录与静态资源就绪状态，供启动器核对和复用 |
| `GET /api/presets` | 可用完整场景 |
| `GET /api/presets/<id>` | 解析后的场景配置 |
| `GET /api/serving-presets` | 可用服务配对示例目录 |
| `GET /api/serving-presets/serving_synthetic` | synthetic 模型与请求的配对配置 |
| `GET /api/serving-schema` | 独立 ServingSpec schema |
| `POST /api/validate` | 普通校验 `{ "config": {...} }`；服务校验附 `"mode":"serve", "serving": {...}` |
| `POST /api/jobs` | 提交 config 与 mode（simulate/estimate/serve）；serve 必须附独立 serving |
| `GET /api/jobs` | 历史与当前任务 |
| `GET /api/jobs/<id>` | 状态、阶段、日志和产物链接 |
| `GET /api/jobs/<id>/config` | 提交时保存的输入配置快照 |
| `GET /api/jobs/<id>/serving` | 服务任务的请求/调度快照；普通任务不提供 |
| `GET /api/jobs/<id>/result` | 有界的可视化摘要 |
| `POST /api/jobs/<id>/cancel` | 取消活动任务 |
| `GET /api/jobs/<id>/artifacts/<filename>` | 下载该任务已登记的产物 |

后端只接受同源网页写入，不提供任意命令执行或任意路径读取接口。输出目录由启动命令确定。

## 开发验证

### 算子结果与执行过程

普通 `simulate` 的时延面板提供 **算子级结果**：推理可切换 TTFT / TPOT，训练可切换平均步、首步及稳态平均步。窗口开销条、耗时排行和详情直接读取后端 `operator_breakdown`；阶段、组件、名称筛选及排序不改变原窗口分母。图中显示耗时最高的 12 项，完整表每页 50 行，可点击算子查看计算、通信、访存、启动、各类等待、争用及未细分服务，并跳转查找对应执行事件。完整数值仍可下载 `operator_breakdown.csv`。

**算子级执行过程**支持按阶段、组件、设备 / Rank、层、token / 训练步和事件类型筛选，可播放 / 暂停、拖动时间、逐事件查看或缩放至筛选事件范围。它回放已经完成的真实仿真记录，运行中的实时状态仍由原阶段与日志面板提供。事件跨度及并发执行不能累加成关键路径时延，也不从回放位置计算任务完成百分比。

全局事件仍均匀采样至 300 条。新的 `operator_execution` 在采样前统计已执行子算子数量，并独立保留最先观测到的 24 个父算子展开链，每链最多 64 个子算子；界面注明链数量及前缀截断，避免全局采样漏掉短链。详情保留引擎提供的实际起止时刻、启动、调度 / 内存准入等待、Matmul、工作负载形状、实现与来源；可选资源工作量未被引擎保留时不重建。元数据和资源明细有显示上限。原始导出也可能精简，完整事件是否可下载以报告导出清单为准。

估算、旧结果缺少账本、未定义窗口均明确显示不可用；中断结果只展示已完成事件。服务模式保留原有请求 / 批次视图，不推测未保存的批内算子轨迹。页面资源增加 `operators.js` / `operators.css`，启动器和健康检查一并检查，无需新增前端构建步骤。

输入编辑的定向回归检查使用 Node.js 内置测试工具，无需安装前端依赖：

```powershell
node --test tests/test_web_input_edit.cjs tests/test_web_views.cjs tests/test_web_serving.cjs tests/test_web_operator_breakdown.cjs tests/test_web_operator_process.cjs
```

检查包含五类参数同步至校验/仿真请求、显示单位换算、无效草稿保留、结构化模型派生参数、历史快照复制及异步响应处理。该测试不替代真实浏览器的布局和交互验收。

Python 的 `tests/test_web_serving.py` 覆盖真实服务/训练 worker、不可变双快照、取消后重提、重启历史、输入限额、完整统计与显示截取。真实浏览器还应检查桌面/手机布局及服务 → 训练 → 估算的结果切换。
