# 自动准备可编辑仿真前端

调用 `supernode-modeling` 时默认先执行此流程。用户明确要求只用 CLI 或不打开网页时，保留其选择。

## 页面来源与运行条件

当前网页直接使用项目中的 `supernode_sim/web_static/index.html`、`app.js`、`topology.js`、`execution.js`、`styles.css`，由 `supernode_sim.web` 提供同源 HTTP API。这些静态文件已随 Python 包分发，不需要 Node、npm、前端依赖安装或打包命令。启动即完成当前版本页面的准备与提供；不要另造脱离引擎的演示页面。

Skill 的可复用入口是本目录上一级的 `scripts/launch_frontend.py`。安装/复制 skill 时保留 `scripts/`、`references/`、`agents/` 和 `subskills/`。前端和数值引擎仍依赖可访问的项目或安装包，不在 skill 内维护第二份前端源码。

## 启动与复用

优先使用用户给定的项目位置。以下命令从项目根目录执行；已复制到其他位置的 skill 应使用其启动脚本的实际绝对路径。

```powershell
python skills/supernode-modeling/scripts/launch_frontend.py --project-root .
```

启动脚本自身只依赖标准库，可由可用的 Python 3.11+ 运行；它优先选择项目 `.venv` 中的 Python 来启动引擎。没有显式项目路径时，按 `SUPERNODE_SIM_ROOT`、当前目录及父目录、skill 所在仓库的位置查找。环境变量或显式路径有误时按返回原因处理，不用任意目录冒充该项目。

这些位置都没有仓库时，脚本尝试使用启动脚本的 Python 中已安装的 `supernode_sim`；此时默认输出位于当前工作目录的 `outputs/skill-web/<端口>/`。安装包不含仓库示例时，通过完整配置导入使用网页。

脚本返回一个 JSON 对象。检查 `status`：

- `started`：已启动并验证本次服务。
- `reused`：匹配当前项目与输出目录的服务已就绪，未再次启动。
- `error`：启动未成功，读取错误信息及日志；不要声称网页已经构建或打开。

成功结果包含实际 `url`、`inputs_url`、`root`、`python`、`output`、`pid` 和 `log` 等运行信息，以真实返回值为准。打开 `inputs_url` 进入输入页；实验页地址由返回的服务 URL 加 `#workspace` 得到。不要假定固定端口。

可指定初始端口和输出基目录：

```powershell
python skills/supernode-modeling/scripts/launch_frontend.py --project-root . --port 8765 --output-root outputs/skill-web
```

默认从 8765 开始，在有限端口范围内寻找匹配服务或可用端口。服务仅绑定 `127.0.0.1`。健康检查用于确认应用身份、项目位置、输出目录和页面资源；只有匹配的服务才复用。未知服务、其他项目或旧版服务占用端口时，选择其他端口，保留原进程。

默认每个端口使用 `outputs/skill-web/<端口>/` 独立任务目录，防止两个后台服务同时管理同一批运行。已有手动启动的 `outputs/web` 任务继续保留在原服务中。后台启动在 Windows 使用隐藏窗口，日志路径随 JSON 返回；启动失败时只清理本次创建的进程。

## 展示与载入用户输入

使用当前环境支持的浏览器工具打开真实返回的 `inputs_url`。已有本任务标签页可复用；不要因重复调用 skill 刷新或覆盖其他标签页的编辑草稿。若环境没有可用浏览器，返回 URL 并说明只能确认 HTTP 服务就绪。远程执行环境的 loopback URL 不等于用户电脑可访问的 URL，只有受支持的端口转发成功时才声称用户可直接访问。

用户已给出完整 YAML/JSON 场景时，先用项目的 `load_config` 解析并保留来源；校准文件按原场景路径解析，导入网页的是包含解析值的完整配置。通过现有“完整配置 JSON”输入或文件导入载入并校验，确认模型、硬件、并行和 workload 与用户场景一致。只有预设或部分需求时，选择适用预设并按用户输入调整；默认 demo 必须保持其 synthetic 标识。

输入页支持五类设置的直接编辑、带单位数值、枚举/布尔选项及复杂字段 JSON。改动同步实验页和下一次仿真提交；未应用的字段 JSON 或类型非法文本会阻止运行。多字段调整完成后统一校验；不自动增加设备容量、重写并行度或抹平变长请求以通过检查。历史任务配置先复制为新的当前配置，再编辑。

浏览器交互应遵循可用工具的接口。不要通过读取浏览器内部存储或执行未支持的页面代码来绕过正常表单操作。常用本地 API 见下一节，可用于代理执行已授权的数值任务。

## 参数驱动的拓扑与执行过程

实验页的“展示依据”同时控制集群拓扑与执行计划。选择当前编辑配置时，参数修改、预设切换和完整 JSON 修改都会更新预览；未校验的内容有明确提示。选择历史或刚提交的任务时，改用该任务独立的配置快照，不能把当前草稿与历史运行结果拼在一起。快照读取失败时留空并提供重试，不回退为其他配置。

- 拓扑按实际模板绘制：Full mesh 为域内全连接、Mesh 使用配置的网格宽度，Clos / Fat tree 按当前引擎的 leaf–spine 模板；显式图仅绘制已配置的有向边，保留孤立 NPU。SO 独立面板默认在 SU 图上方，显示卡组接入、SU gateway、SO spine、逐方向带宽和独立注入约束；查看 SU 域内链路时 SO 面板仍保留。显式 SO 图仅提取 `domain=SO` 的边，不推测 SO 域划分，无 SO 边则说明未配置。SO 与 SU 分别分页，点击 SO 图中的 SU 可定位域内视图并查看物理卡的 rank、主机及并行坐标。大规模图标明展示数量；图形位置不代表物理距离或实际拥塞。
- 执行计划根据训练步数、梯度累积、变长请求、TP/SP/PP/EP/DP/FSDP、重计算、卸载、PD 双池和投机解码生成。它描述依赖关系，不是事件级完成进度。仅一个输出 token 的请求没有额外 Decode 循环。SP 使用 `execution.sequence_parallel` 开关：启用时度数等于 TP，关闭时为 1，不额外乘入总卡数；配置面板、输入总览、执行摘要与拓扑设备详情同步展示。
- 运行结束后，实际阶段使用结果的 `execution_summary`；阶段条表示首个事件开始至最后事件完成的跨度，可相互重叠。部分执行明确标注中断，旧任务缺少摘要时显示不可用。`estimate` 仅展示计划与必要下界，不显示实际阶段耗时或完成百分比。

## 与仿真任务衔接

启动页面只准备交互环境；用户请求“打开/查看/编辑配置”时，不自动点击“开始模拟”。用户已经请求仿真或估算时，继续完成数值工作，无需再为该任务确认。

网页支持 `estimate`、`simulate` 和 `serve`：

1. 以完整 `Config` 调用 `POST /api/validate`，请求体为 `{"config": {...}}`。
2. 调用 `POST /api/jobs`，请求体为 `{"config": {...}, "mode": "simulate"}`（或 `estimate`）。记录返回的任务 ID。
3. 使用 `GET /api/jobs/<id>` 读取真实阶段、日志及最终状态；不生成假进度。
4. 完成后用 `GET /api/jobs/<id>/result` 获取可视化摘要，在同一服务的网页历史中选择该任务展示；下载文件链接使用返回的 `artifacts`。

服务模式在校验和提交时传 `{"config": {...}, "mode": "serve", "serving": {...}}`。用 `GET /api/serving-presets/serving_synthetic` 读取成对 synthetic 示例，或在独立请求表/服务 JSON 中录入。历史服务负载位于 `GET /api/jobs/<id>/serving`，恢复时与 config 一起复制，普通任务不借用旧服务草稿。DP=1、inference 及不支持 PD/投机的限制由后端校验，网页不转换成固定 batch 代替。

服务结果展示完整总体分位、goodput、请求状态及相对批次时间线；训练展示阶段/dtype FLOPs 与 MFU；执行证据分别显示 trace/kernel/collective 覆盖，不等同精度。网页服务上限为 10,000 请求、每批 1,024、128 实例及 2 MiB 请求体，超限保留输入并提示使用 CLI。

收到任务 ID 后保留并继续读取该任务，不能因轮询失败重新提交。提交响应不确定时，先检查任务列表和输入配置确认是否已创建；没有证据时不要重复运行。`GET /api/jobs/<id>/config` 是提交时的独立快照，不是当前网页草稿。

`infeasible`、`slo_failed`、`estimated` 与运行失败按原引擎口径解释；`estimate` 不证明 SLO 可行。通信统计、内存和时间线展示可能有数量限制，完整结果以导出清单为准。

`sweep`、`size-su`、`feedback`、流式推理和检查点实验仍使用各自 CLI/API。网页可展示基础输入，但不把这些命令的结果冒充网页支持的任务类型，也不重跑已完成的大实验只为填充图表。

## 故障与交付

启动器不自动安装依赖。缺少依赖或页面资源时，先检查实际项目和 Python 路径；按已授权范围使用项目声明的依赖修复，重新检查后再试。修复参数优先使用返回的 `repair_argv`；使用 `repair_command` 时匹配其声明的 shell，保留路径引号。失败原因没有变化时停止重复启动，提供具体错误及日志，继续不依赖网页的已授权分析。

浏览器工具不可用、访问失败和服务启动失败是不同状态，分别报告。交付实际 URL、配置来源、任务 ID/输出目录及已完成验证；不把 helper 返回成功当作浏览器视觉验收。保留交付的服务供用户操作，需要停止时仅处理本次已确认归属的服务，不终止其他占用相同端口或项目的进程。
